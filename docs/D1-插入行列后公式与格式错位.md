# D1 缺陷说明：当前工作表插入/删除行列后，公式与单元格格式错位

| 项 | 内容 |
|---|---|
| 编号 | D1 |
| 严重级别 | **P0**（静默数据错位，无异常、无提示） |
| 影响版本 | 1.10.0（1.9.5 起即存在，1.10.0 新增的重载放大了影响面） |
| 影响范围 | `InsertRows()` / `DeleteRows()` / `InsertColumns()` / `DeleteColumns()` 的**当前工作表**路径 |
| 是否影响非当前表 | **否**，非当前表分支实现完整 |
| 发现方式 | 宿主侧 headless 回归探针（SpreadaloniaProbe P10/P11） |

---

## 1. 摘要

在当前工作表上插入或删除行列时，**`Data` 平移正确，但 `FormulaCells` 没有重建、`NumericCells` 等 9 个集合没有平移**，
导致公式与数字格式"留在原地"，套到了被挤过来的别的数据上。

后果：报表插入一行后，原本 `A44` 的 `=SUM(A41:A43)` 会显示在 `A45`；原本挂在 `A62` 的金额格式会套到 `A61` 的数字上。
两者都是**静默**发生的，不抛异常。

---

## 2. 复现

```csharp
// 1) 三行数据 + 一个求和公式，公式在 row 43
SetData(sp, (0, 40, "1"), (0, 41, "2"), (0, 42, "3"));
sp.SetFormula(0, 43, "SUM(A41:A43)");
sp.RecalculateAll();

// 2) 在 row 41 前插入 1 行
sp.InsertRows(sp.CurrentSheet, 41, 1);
```

**实测输出**（`probe-result.txt:334-345`）：

```
before: A44 formula="SUM(A41:A43)" data="=SUM(A41:A43)" value=6

after InsertRows(sheet,41,1):
  A42: formula=""  data="<key (0,41) not present>"   ← 新插入的空行，正确
  A43: formula=""  data="2"                          ← 原 A42，正确
  A44: formula="SUM(A41:A43)"  data="3"              ← ✗ 公式错位：这里实际是 "3"
  A45: formula=""  data="=SUM(A41:A43)"              ← ✗ 公式原文到了这里，但引擎不认识它
```

`Data` 完全正确（`"2"→A43`、`"3"→A44`、`"=SUM→A45"`），错的是 `FormulaCells` 仍停在 `(0,43)`。

**NumericCell 同样错位**（`probe-result.txt:347-352`）：

```
before: data(0,61)="200"  numeric(0,61)=YES
after InsertRows(60,1):
  data(0,61)="100"  data(0,62)="200"     ← 数据正确下移
  numeric(0,61)=YES                       ← ✗ 格式留在原位，套到了 "100"
  numeric(0,62)=no                        ← ✗ 应该在这里
```

## 3. 根因

### 3.1 入口：新重载的"当前表"分支回退到了旧实现

四个重载都是同一个模式，以 `InsertRows` 为例：

```5495:5500:Spreadalonia/Spreadsheet.axaml.cs
if (this.CurrentSheet == sheet)
{
    this.Selection = ImmutableList.Create(new SelectionRange(0, index, sheet.MaxTableWidth, index + count - 1));
    this.InsertRows();     // ← 回退到 1.9.5 的无参旧实现
    return;                // ← 后面的完整逻辑被跳过
}
```

同样的 `return` 存在于：

| 方法 | 行号 |
|---|---|
| `InsertColumns(SpreadsheetSheet,int,int)` | `5298-5303` |
| `DeleteColumns(SpreadsheetSheet,int,int)` | `5398` 附近 |
| `InsertRows(SpreadsheetSheet,int,int)` | `5495-5500` |
| `DeleteRows(SpreadsheetSheet,int,int)` | `5594` 附近 |

### 3.2 被回退到的旧实现只处理了一半集合

`InsertRows()`（`4056-4089`）只平移了 7 个字典，**没有**处理公式、数字格式等：

```4065:4075:Spreadalonia/Spreadsheet.axaml.cs

table.CellForeground = table.CellForeground.InsertRows(selection, this.UndoStackCellForeground);
table.CellMargin = table.CellMargin.InsertRows(selection, this.UndoStackCellMargin);
table.CellTextAlignment = table.CellTextAlignment.InsertRows(selection, this.UndoStackCellHorizontalAlignment);
table.CellTypefaces = table.CellTypefaces.InsertRows(selection, this.UndoStackCellTypeface);
table.CellVerticalAlignment = table.CellVerticalAlignment.InsertRows(selection, this.UndoStackCellVerticalAlignment);
```

`InsertRows(SpreadsheetSheet,int,int)` 的 `5518-5583` 做全了，可直接作为修复模板：


## 4. 修复建议

### 方案 A（推荐）：抽取共用内核

把 `5518-5583` 的逻辑抽成内部方法，四个无参方法与四个重载共用：

```csharp
private void ShiftRowsCore(SpreadsheetSheet sheet, SelectionRange range, bool useUndo)
```

- `useUndo == true`：传入 `this.UndoStack*` 系列（当前表路径）
- `useUndo == false`：传入局部 `Stack<>`（非当前表路径）

这样两条路径行为一致，也不会再出现"改了一边忘了另一边"。

> 注意：`UndoStackNumericCell / UndoStackCellFontSize / UndoStackTitleCell / UndoStackLinkCell /
> UndoStackButtonCell / UndoStackTreeCell` **这些字段目前不存在**（全文件搜索无命中），
> 说明这几个集合从未参与 undo。补平移时需先决定：
> - 用临时 `Stack<>`（改动最小，但这几个集合不可撤销）；
> - 或新增对应 `UndoStack*` 字段（撤销完整，改动较大）。
>
> 现状是"完全不动"，比"动了但不可撤销"更糟；建议先用临时栈，把 undo 一致性记为已知限制。

### 方案 B（最小改动）：无参版末尾补齐

在 `InsertRows()` 的 `table.RowHeights = ...`（`4075`）之后、`ClearRedoStack()`（`4081`）之前插入：

```csharp
SelectionRange selection = this.Selection[0];

table.CellFontSize = table.CellFontSize.InsertRows(selection, new Stack<ValueStackFrame<(int, int), double>>());
table.TitleCells   = table.TitleCells.InsertRows(selection, new Stack<StackFrame<(int, int), TitleCell>>());
table.LinkCells    = table.LinkCells.InsertRows(selection, new Stack<StackFrame<(int, int), LinkCell>>());
table.ButtonCells  = table.ButtonCells.InsertRows(selection, new Stack<StackFrame<(int, int), ButtonCell>>());
table.TreeCells    = table.TreeCells.InsertRows(selection, new Stack<StackFrame<(int, int), TreeGradeCell>>());
table.NumericCells = table.NumericCells.InsertRows(selection, new Stack<StackFrame<(int, int), NumericCell>>());

// 公式：清空缓存与依赖图，从平移后的 Data 重建
table.FormulaCells.Clear();
table.FormulaEngine.Clear();
this.RecalculateSheet(sheet);

// HiddenRows：>= selection.Top 的 + Height
HashSet<int> newHidden = new HashSet<int>();
foreach (int h in sheet.HiddenRows) newHidden.Add(h >= selection.Top ? h + selection.Height : h);
sheet.HiddenRows.Clear();
foreach (int h in newHidden) sheet.HiddenRows.Add(h);

// MergedRanges / ReadonlyRanges：Top >= selection.Top 的整体下移 Height（照 5556-5581）
```

`DeleteRows()` / `InsertColumns()` / `DeleteColumns()` 需做对应的同构补齐（删除时 `RecalculateSheet` 同样必须调用）。

> `RecalculateSheet` 当前是 `private`（`5683`），同类内可直接调用；若将来需要在宿主侧主动触发，可考虑提升为 `public`。

## 6. 宿主侧临时规避（修复前可用）

报表设计器本来就维护 `formulas[] = {row, col, formula}`，因此在插入/删除行列后由宿主：

1. 用 `RowsInserted` / `RowsDeleted` / `ColumnsInserted` / `ColumnsDeleted` 事件拿到 `StartIndex` 与 `Count`；
2. 平移 `formulas[]` 中的坐标；
3. 对受影响的区域重新 `SetFormula` + 重新挂 `NumericCell`。

这样可以绕开 D1，等控件修复后删掉这段补偿逻辑。
