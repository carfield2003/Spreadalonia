# Spreadalonia 改动需求（会计报表设计器）

> 适用版本：**1.9.5 → 1.10.0**
> 需求方：宿主项目 SSFinance（Avalonia）要用 Spreadalonia 实现会计报表设计器
> （对齐 WPF 版 `SSFinanceWin/FormReportTemplate.xaml`）。
>
> 本文只列**必须在本仓库改**的项。打印设置、自有文件格式、公式解析与云端计算等均在宿主侧实现，
> 见文末"不需要改"。
>
> 所有坐标均指当前 1.9.5 源码行号。

---

## 背景（决定下面每一条需求的两个事实）

1. 报表的**金额列几乎全部由公式产生**，必须显示千分位与固定小数位，且导出 Excel 后仍是活公式。
2. 宿主在表格之外维护了一份 `formulas[] = {row, col, formula}`，所以**必须能感知行列增删**。

---

## R1（P0，阻塞）公式单元格必须套用 NumericCell 格式化

### 问题 A：渲染 —— 公式单元格挂了 NumericCell 会显示空白

`Table.cs:3537` 取到的 `txt` 来自 `Data`，即**公式原文**（如 `"=A1/A2"`）：

```csharp
// Table.cs:3537
bool hasData = Data.TryGetValue((left + x, top + y), out string txt);
```

`Table.cs:3697-3708` 把它直接喂给 `GetDisplayText`（该方法对非数值返回**空串**）：

```csharp
// Table.cs:3697-3708  （现状）
string displayText = txt;
NumericCell activeNumericCell = null;

if (NumericCells.TryGetValue((left + x, top + y), out NumericCell numericCell) && numericCell != null)
{
    activeNumericCell = numericCell;
    displayText = numericCell.GetDisplayText(txt);        // txt = "=A1/A2" → ""
}
else if (FormulaCells != null && FormulaCells.TryGetValue((left + x, top + y), out CellData formulaCell))
{
    displayText = formulaCell.DisplayText;
}
```

后果：挂了 NumericCell 的公式单元格显示**空白**；没挂的显示 `DisplayText`（`50`），无千分位与小数位。

**改为**（先求出待格式化的文本，再统一交给 NumericCell）：

```csharp
string displayText;
NumericCell activeNumericCell = null;

CellData formulaCell = null;
if (FormulaCells != null)
{
    FormulaCells.TryGetValue((left + x, top + y), out formulaCell);
}

// 公式单元格以计算结果为原文，其它单元格以 Data 里的原文
string rawText = formulaCell != null ? formulaCell.DisplayText : txt;

bool numberResult = formulaCell == null || formulaCell.ValueType == CellType.Number;

if (numberResult &&
    NumericCells.TryGetValue((left + x, top + y), out NumericCell numericCell) && numericCell != null)
{
    activeNumericCell = numericCell;
    displayText = numericCell.GetDisplayText(rawText);
}
else
{
    displayText = rawText;
}
```

约束：`ValueType != CellType.Number`（文本 / 布尔 / 错误）时**不要**套 NumericCell，
否则 `=IF(A1>0,"有","无")` 会被格式化成空串。

合并区内的公式单元格同理，见 `Table.cs:3997`（`mergedFormulaCell`），按同一规则处理。

### 问题 B：导出 —— 公式单元格不写 NumberFormat

`XlsxExporter.cs:388-393` 命中公式后直接 `continue`，根本走不到 401 行的数字格式逻辑；

```csharp
// XlsxExporter.cs:401-406  （仅普通数据单元格走了这里）
if (isNumeric && NumberFormatter.TryParse(rawText, out decimal numericValue))
{
    cell.Value = numericValue;
    cell.Style.NumberFormat.Format = numericCell.Digits > 0
        ? "#,##0." + new string('0', numericCell.Digits)
        : "#,##0";
    ...
}
```

而 `WriteFormulaCell`（`XlsxExporter.cs:735-763`）只写公式或缓存值，**完全不写 NumberFormat**。

**改为**：把上面那段格式串生成抽成

```csharp
private static string GetNumberFormat(NumericCell nc)
    => nc.Digits > 0 ? "#,##0." + new string('0', nc.Digits) : "#,##0";
```

（也建议给 `NumericCell` 加一个 `public string GetNumberFormat()`，渲染与导出共用。）

并在 `WriteFormulaCell` 末尾（`ApplyCommonStyle` 之前）补上：

```csharp
if (table.NumericCells != null &&
    table.NumericCells.TryGetValue((c, r), out NumericCell nc) && nc != null &&
    formulaCell.ValueType == CellType.Number)
{
    cell.Style.NumberFormat.Format = GetNumberFormat(nc);
    cell.Style.Alignment.Horizontal = XLAlignmentHorizontalValues.Right;

    if (nc.NegativeRed && formulaCell.CachedValue is decimal dv && dv < 0)
    {
        cell.Style.Font.FontColor = XLColor.Red;
    }
}
```

两条导出路径（写公式 / `WriteCachedValue` 降级为值）都会经过这里，均需生效。

### 验收

| 场景 | 期望 |
|---|---|
| B1 挂 `NumericCell{Digits=2}` + `=A1/A2`，A1=100、A2=2 | 屏幕显示 `50.00` |

## R2（P0）暴露公式读写 API

`SpreadsheetSheet.FormulaCells` 目前是 **internal**：

```csharp
// SpreadsheetSheet.cs:112
internal Dictionary<(int, int), CellData> FormulaCells { get; set; } = new Dictionary<(int, int), CellData>();
```

`Data` 里永远是公式原文，宿主想拿计算结果只能自己调 `FormulaEngine.Evaluate(...)`
或 `CascadeRecalculate(...)`，容易与内部缓存不同步。

**改为**：

1. `SpreadsheetSheet.cs:112` → `public Dictionary<(int, int), CellData> FormulaCells { get; internal set; }`
2. 在 `Spreadsheet.axaml.cs` 新增（作用于 CurrentSheet，另配带 `SpreadsheetSheet` 的重载，
   与 `SetData` / `InsertColumns` 的重载风格一致）：

```csharp
// 返回不带前导 "=" 的公式表达式；非公式单元格返回 null
public string GetFormula(int col, int row);
public string GetFormula(SpreadsheetSheet sheet, int col, int row);

// 接受带或不带 "=" 的写法；等价于写入 "=" + formula 并进入引擎
public void SetFormula(int col, int row, string formula);
public void SetFormula(SpreadsheetSheet sheet, int col, int row, string formula);

// 公式单元格取 FormulaCells 的条目，否则 CellData.FromText(Data[(col,row)])
public CellData GetCellData(int col, int row);
public CellData GetCellData(SpreadsheetSheet sheet, int col, int row);
```

## R3（P1）补齐内置函数

`Formula/FunctionRegistry.cs:119-155`（构造函数内的 `Register` 列表）目前只有 **29 个**，
**缺 `FLOOR`** —— 宿主真实报表公式里就在用：

```
20+C1+FLoor(QC("1002","年","默认","是","是","")+LFS("500101010106","月","借","是","是",""))+B5
```

**需补**：`FLOOR`、`CEILING`、`ROUNDUP`、`ROUNDDOWN`、`MOD`、`INT`、`IFERROR`、`SUMIF`、`COUNTIF`。
实现参照同文件既有的 `Sum` / `Round` 等私有静态方法。

**注意（好消息）**：导出白名单 `XlsxExporter.cs:100 ExcelFunctions` **已包含**
`FLOOR`、`CEILING`、`MOD`、`INT`、`SUMIF`、`ROUNDUP`、`ROUNDDOWN`，
所以只需在 `FunctionRegistry` 注册实现，**不必改白名单**。
仅 `IFERROR` / `COUNTIF` 需确认是否已在白名单，不在则加入。

## R4（P1）导出前自动重算

`Spreadsheet.axaml.cs:1900 SaveXlsx(Stream, XlsxExportOptions)` 直接调导出器，未重算：

```csharp
// Spreadsheet.axaml.cs:1912
XlsxExporter.Export(ContentTable, stream, options);
```

后果：宿主改完数据若未显式调 `RecalculateAll()`，`ExportFormulas=false` 导出的是**过期缓存值**
（实测 A1 已改为 100，E1 正确变 105，而 F1 仍导出旧值 30）。

**改为**：

1. `XlsxExportOptions` 增加 `public bool RecalculateBeforeExport { get; set; } = true;`
2. `SaveXlsx(Stream, XlsxExportOptions)` 在 `1912` 行前按该选项调用 `RecalculateAll()`（`4976` 行）
3. 多表重载 `SaveXlsx(Stream, IReadOnlyList<SpreadsheetSheet>, ...)`（`1929` 行）同样处理，
   对每个待导出 sheet 重算（`RecalculateSheet(sheet)`）

## R5（P1）行列增删事件

`Spreadsheet.axaml.cs` 四个方法都没有事件：
`InsertColumns()` `3921`、`DeleteColumns()` `3954`、`InsertRows()` `3987`、`DeleteRows()` `4020`。

宿主维护了 `formulas[] = {row, col, formula}`，用户在表格 UI 上插入一行后，
公式里的 `B5` 必须整体下移，目前**无从感知**。

**改为**：在 `SpreadsheetSheet.cs` 末尾（`SheetEventArgs` 同一风格，构造函数 internal）新增

```csharp
public sealed class RowsChangedEventArgs : EventArgs
{
    public SpreadsheetSheet Sheet { get; }
    public int StartIndex { get; }   // 插入/删除的起始行号
    public int Count { get; }        // 行数
}

public sealed class ColumnsChangedEventArgs : EventArgs
{
    public SpreadsheetSheet Sheet { get; }
    public int StartIndex { get; }   // 起始列号
    public int Count { get; }        // 列数
}
```

在 `Spreadsheet.axaml.cs` 新增四个事件，并在上述四个方法末尾（`InvalidateVisual()` 之后）触发：

```csharp
public event EventHandler<RowsChangedEventArgs> RowsInserted;
public event EventHandler<RowsChangedEventArgs> RowsDeleted;
public event EventHandler<ColumnsChangedEventArgs> ColumnsInserted;
public event EventHandler<ColumnsChangedEventArgs> ColumnsDeleted;
```

插入位置与数量在无参版里取自 `this.Selection[0].Top` / `.Height`（行）与 `.Left` / `.Width`（列）。

## R6（P1）InsertRows / DeleteRows 程序化重载

列有程序化重载，行没有：

| 操作 | 无参版 | 程序化重载 |
|---|---|---|
| 插入列 | `3921` | `5128 InsertColumns(sheet, index, count)` ✅ |
| 删除列 | `3954` | `5235 DeleteColumns(sheet, index, count)` ✅ |
| 插入行 | `3987` | **缺失** ❌ |
| 删除行 | `4020` | **缺失** ❌ |

**改为**：新增

```csharp
public void InsertRows(SpreadsheetSheet sheet, int index, int count)
public void DeleteRows(SpreadsheetSheet sheet, int index, int count)
```

**照 `5128` 行 `InsertColumns(SpreadsheetSheet, int, int)` 的模式实现**：
当前表 → 构造 `SelectionRange` 后复用无参版；非当前表 → 手动平移各字典
（`Data` / `CellForeground` / `CellMargin` / `CellTextAlignment` / `CellTypefaces` /
`CellVerticalAlignment` / `CellFontSize` / `TitleCells` / `LinkCells` / `ButtonCells` /
`TreeCells` / `NumericCells` 与行级集合）。

这两个重载应同时触发 R5 的事件。
